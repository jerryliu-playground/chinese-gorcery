# M13 口碑系统与更多顾客 · agent 的决定（待 Jerry 确认）

所有平衡数值都在 `data/reputation.json`（整个文件标了 `"_tbd": true`）和 `data/customer_types.json` 的四个新顾客类型里。下面列出的都是占位值，可以直接改数据，不用改代码。

## 1. 口碑与星级

| 项目 | 占位值 | 说明 |
| --- | --- | --- |
| 初始口碑 | 40 | spec 给的占位 |
| 星级门槛 | 0 / 25 / 50 / 70 / 85 | 口碑 ≥ 门槛就是 1/2/3/4/5 星。开局 40 = 2 星 |
| 每日拉动速度 | 20% | 打烊时：新口碑 = 旧口碑 + (当天平均满意度 − 旧口碑) × 20%。当天没有顾客就不变 |
| 客流系数 | 口碑 0 → ×0.6，40 → ×1.0，100 → ×1.6（中间按直线） | 普通客流和熟食高峰客流都乘这个系数。开局 40 = ×1.0，所以第一天和以前一样 |
| 应聘者质量 | 口碑 ≤40 不变；100 时，属性随机范围的下限抬高 40% | 例：若速度范围是 800–1200，口碑 100 时变成 960–1200，仍在原范围内 |

口碑内部按千分之一存，显示时取整数。

**给其他系统的接口**：`GameSim.NudgeReputation(int 点数, string 原因翻译键)`，加减整数口碑（自动限制在 0–100），发出 `ReputationChanged` 事件，HUD 会显示"口碑 +3：原因"。M12 的卫生检查、节日装饰、事件选择，M15 的竞争对手，都调用这个方法即可。

## 2. 顾客满意度（每位顾客离店时打一次分，0–100）

| 情况 | 加减 |
| --- | --- |
| 基础分 | 50 |
| 每买一件 | +5（最多 +25） |
| 每次找不到货 | −15 |
| 每次嫌贵没买 | −6 |
| 等不及生气离开 | −40 |
| 排队时间超过耐心的一半 | −10 |
| 冒爱心（找到流行商品时） | 每个 +10 |
| ABC 青少年找到流行商品 | +15 |
| ABC 青少年没找到流行商品 | −30（另外还有"找不到货"的 −15，合计大降） |
| 本地顾客：店里有双语价签 | +10 |
| 本地顾客：没有价签且冒了问号 | −8 |

一开始基础分是 60，但这样"什么都没买到"的顾客也有 48 分，比开局口碑 40 还高，空店口碑反而会涨，所以改成 50 / −15。

## 3. 新顾客类型（customer_types.json）

| 顾客 | 出现条件 | 到店权重 | 偏好 | 其他 |
| --- | --- | --- | --- | --- |
| ABC 青少年 `abc_teen` | 2 星 | 2，每多 1 星 +1 | 零食 5、饮料 5、熟食 3、冷冻 1、干货 1 | 耐心 10 分钟，清单 1–3 件，追流行商品 |
| 本地顾客 `local_a` | 3 星 | 2，每多 1 星 +1 | 熟食 4、酱料 3、零食 3、水果 2、饮料 1 | 在意英文标签 |
| 本地吃货 `local_b` | 3 星 | 1，每多 1 星 +1 | 酱料 4、熟食 3、果蔬 3、零食 2、冷冻 1 | 在意英文标签 |
| 餐馆采购 `restaurant_buyer` | 3 星，且店里有肉类冷柜和海鲜设施（鱼池 / 龙虾蟹缸 / 冰台） | 1 | 肉 5、海鲜 4、干货 3、酱料 2 | 清单 5–9 件，付完款可能下团购订单 |

- 老顾客类型的权重不变，所以星级越高，新顾客占比越大（"顾客构成随口碑变化"）。
- 顾客中文名（ABC 青少年、本地顾客、本地吃货、餐馆采购）和每类 3 句台词都是草稿，待审。

## 4. 流行商品

- 每季开始时，从"零食、饮料"里、店里现在能进到的商品（批发能订，或进口已解锁）中随机选 1–2 种，持续一季。用单独的种子随机数流，不影响顾客。
- **季节暂定**：`GameSim.SeasonOf(day) = (day − 1) / 28`，只有这一个方法决定季节。M12 日历合并后把这个方法接到日历上即可。
- ABC 青少年进店时 80% 的概率专门来找某个流行商品（放在购物清单第一项）。找到后 30% 概率冒爱心，每个爱心让同类顾客 30 分钟后多来 1 人（口口相传，打烊后不来）。
- 店里左上角显示"这季流行：XX"，新一季开始时 HUD 也会提示。

## 5. 双语价签

- 一次性购买 $400，阶段 1 就能买，在"升级"面板里。费用记在"设施花费"里。
- 有价签：本地顾客购买概率 ×1.15（不超过 100%），购物清单多 1 件，满意度 +10。
- 没价签：本地顾客每看一件商品有 30% 概率冒问号（每人最多一次），满意度 −8。

## 6. 餐馆团购订单

| 项目 | 占位值 |
| --- | --- |
| 下单概率 | 餐馆采购付完款后 30% |
| 同时进行中的订单 | 最多 1 个（数据 `maxActive`） |
| 每单商品种数 | 1–2 种 |
| 可能要的商品 | 五花 10–20、排骨 10–20、猪梅肉 3–6、整鸭 3–6、蛤蜊 10–20、香米 10–20、蚝油 10–20、生抽 10–20、米粉 10–20（只选店里有仓库放得下的） |
| 期限 | 接单后 2–4 天 |
| 报酬 | 建议售价 × 80%（批发价） |
| 按时交付 | 口碑 +4 |
| 超时或不够 | 取消，口碑 −6 |

做法（agent 的理解，待审）：
- 订单请求在面板里保留到第二天开店前，没回应就过期（不扣口碑）；拒绝也不扣口碑。
- 有请求在等、或已有进行中的订单时，不会再来新的请求。
- 接单后，**仓库（后仓 / 冷库）里**的对应商品会被"预留"出来，不再上架、不会卖掉；每天早上到货后、接单时、打烊时都会再预留一次。货架上已经摆着的不算。
- 备齐后在当天打烊时自动交付，货款记入当天营收（按商品记销量）。
- 到期那天打烊还没备齐：取消，预留的货退回仓库。预留的货也会过期（比如肉），过期就丢弃、算损耗，需要重新预留。
- 活鱼、活虾没放进候选（它们要进鱼池，预留会很复杂）。spec 例子里的"10 条活鱼"先不做，需要的话再加。

## 7. 点评

- 每天打烊生成 2–3 条（当天发生的事少于 2 件就更少，没顾客就没有）。每条讲不同的事；好事和坏事都有时，好坏交替，让玩家看到哪里做得好、哪里要改。
- 只引用当天真实发生的事，每条带上发生最多的那个商品、以及当时的顾客类型（显示为"谁写的"）。
- 保留最近 30 条。点评面板显示口碑分数、星级、流行商品、价签状态、口碑走势图（每天打烊后的口碑）和最近 12 条点评。
- "排队太久"：有付了钱的顾客排队 ≥ 8 分钟；"结账很快"：当天至少 10 位顾客付款，且没人排队太久、没人生气离开。

## 9. SimRunner 对照（60 天）

`--good-service`：雇收银员和理货员，每种商品备货 60；`--poor-service`：不额外雇人，每种商品只备 8 件，主角最后才去收银。

| 种子 | 好服务：口碑 / 星 | 差服务：口碑 / 星 | 好服务：最后 7 天日均客流 | 差服务：最后 7 天日均客流 |
| --- | --- | --- | --- | --- |
| 1 | 50 / 3 星 | 33 / 2 星 | 118.4 | 69.3 |
| 2 | 53 / 3 星 | 34 / 2 星 | 81.0 | 72.1 |
| 3 | 51 / 3 星 | 34 / 2 星 | 123.6 | 70.7 |

好服务 60 天里本地顾客、餐馆采购都出现了；差服务一直只有 2 星，只来老顾客和 ABC 青少年。客流差别一部分来自口碑系数（×1.10 对 ×0.93），一部分来自好服务开了熟食部（午晚高峰客流）。
